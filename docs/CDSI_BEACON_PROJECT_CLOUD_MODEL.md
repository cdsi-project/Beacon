# CDSI Beacon 项目与云备份模型

> 状态：下一阶段设计，尚未在当前发布版本 v0.200 中完整实现
>
> 适用范围：本地项目、云端项目、同步、取回、删除与迁移
>
> 当前实现基线：已发布的 v0.200；根目录 `VERSION` 为版本来源

## 1. 目标

Beacon 的本地资产与云端备份都按项目管理。用户面对的是项目，而不是孤立的对象键、Bucket 目录或上传任务。

本设计需要保证：

- 一个逻辑项目在本地和所有云提供商上保持同一个稳定身份。
- 项目改名不会改变项目身份，也不会导致重复上传或错误合并。
- 同名项目可以共存，任何冲突都不得静默覆盖。
- 同步、取回、删除和状态展示都以项目为入口。
- 单个资源仍保留独立校验、重试和审计能力。
- v0.200 已有的“项目名称/文件名”备份可以继续识别和迁移。

## 2. v0.2.13 当前行为

当前已经实现：

- 本地项目具有稳定项目 ID，项目名称是可见属性。
- 一个资产可以加入多个项目，也可以暂时不属于项目。
- 当前界面中的新云端备份必须由项目发起，项目可以绑定零个、一个或多个备份配置；底层仍保留可生成旧式无项目对象键的兼容调用路径，但当前界面不使用。
- 每个远端对象完成后记录大小、SHA-256、提供商、对象键和备份时间。
- 相同对象键且内容一致时复用；内容不同时拒绝覆盖。
- 云端取回和删除只操作用户明确选择并确认的已登记副本。

当前兼容边界：

- 远端对象键仍为 `<项目名称>/<原文件名>`。
- 云备份管理仅依据对象键中可解析的单层目录前缀进行分组；无法解析的旧对象键归入“未归属项目”。分组不读取本地项目关系，也不代表稳定项目身份。
- 云端没有独立的项目清单，无法只靠 Bucket 完整重建本地项目。
- 同一备份配置中的同名项目可能产生对象键冲突。
- 删除本地项目不会删除云端副本，也不会改变现有对象键前缀分组。
- 双击项目可以修改本地名称和类型；项目 ID、成员和备份绑定不变。改名不会移动或重命名既有云端对象，后续同步仍按新的项目名称生成对象键，因此旧名称前缀在迁移前可能继续显示为独立云端分组。
- 当前左侧“删除备份项目”按前缀分组逐项删除已登记副本，不是基于 ProjectId/manifest 的项目删除。
- 应用服务已有复制并校验新对象、更新映射后尝试删除旧对象的重命名原语；旧对象删除失败时会保留警告和旧对象。当前项目改名只更新本地项目元数据，界面尚未提供旧布局迁移入口，不能把该对象重命名原语视为项目改名时的自动行为。

这些行为必须继续兼容，但不应作为新的身份模型继续扩展。

## 3. 核心不变量

### 3.1 项目身份

- `ProjectId` 是不可变的全局稳定标识。
- `Name` 是可修改的显示名称，不参与身份判断。
- 本地数据库、云端清单和所有同步审计使用同一个 `ProjectId`。
- 项目复制必须生成新的 `ProjectId`；项目取回必须保留原 `ProjectId`。

### 3.2 资源身份

- `AssetId` 是逻辑资源身份，文件名和路径不是身份。
- 项目清单以 `AssetId + SHA-256 + Size` 描述一次确定的资源内容。
- 原文件名作为用户可见信息保留，但同名不同内容不能写入同一个对象。

### 3.3 操作独立性

以下操作互不隐含：

- 从项目移出资源
- 删除本地项目
- 删除本地文件
- 删除云端项目副本
- 从资产列表隐藏资源

每项操作都必须明确说明影响范围并保留审计记录。

## 4. 目标云端布局

推荐使用稳定 ID 作为对象键主目录：

```text
beacon/
  projects/
    <ProjectId>/
      project.json
      assets/
        <AssetId>/
          <OriginalFileName>
```

项目名称写入 `project.json`，不写入身份路径。这样项目改名只更新清单，不需要搬移所有对象。对象的最后一段保留原文件名，便于用户在云服务控制台识别。

每个备份配置形成一个独立项目副本。多个提供商之间不共享对象 URL，也不能把某个提供商的成功状态推断为其他提供商成功。

## 5. 项目清单

`project.json` 至少包含：

```json
{
  "schemaVersion": 1,
  "projectId": "稳定项目 ID",
  "name": "项目显示名称",
  "projectType": "video",
  "revision": 7,
  "updatedAtUtc": "2026-08-22T10:00:00Z",
  "beaconVersion": "0.xxx",
  "assets": [
    {
      "assetId": "稳定资源 ID",
      "originalFileName": "clip-01.mp4",
      "objectKey": "beacon/projects/<ProjectId>/assets/<AssetId>/clip-01.mp4",
      "size": 123456789,
      "sha256": "...",
      "addedAtUtc": "2026-08-22T09:00:00Z"
    }
  ]
}
```

清单自身也应保存 SHA-256 或使用对象存储版本号 / ETag 进行并发校验。同步顺序为“上传并验证资源，最后提交新清单”；不能先发布一个引用未完成资源的清单。

## 6. 项目状态

每个“本地项目 + 备份配置”组合独立计算状态：

| 状态 | 含义 |
| --- | --- |
| 仅本地 | 本地存在，云端没有已确认项目清单 |
| 待同步 | 本地成员或元数据相对云端有变化 |
| 同步中 | 正在上传、校验或提交清单 |
| 已同步 | 清单和全部目标资源均通过校验 |
| 部分同步 | 至少一个资源成功，但项目清单尚未完整提交 |
| 仅云端 | 云端清单存在，本机尚未建立对应项目 |
| 冲突 | 同一 ProjectId 的本地与云端都发生了不能自动合并的变化 |
| 异常 | 清单损坏、对象缺失、校验失败或凭据不可用 |

项目绑定多个提供商时，界面显示总体状态，并允许展开查看每个提供商的独立状态。

## 7. 同步与冲突规则

| 检测结果 | 默认处理 |
| --- | --- |
| 云端无相同 ProjectId | 创建项目副本，验证资源后提交清单 |
| ProjectId 相同，云端版本未变化 | 上传本地差异并提交下一版清单 |
| ProjectId 相同，本地无变化 | 复用云端状态，不重复上传 |
| ProjectId 相同，双方均有变化 | 标记冲突，要求用户选择合并、保留本地或取回为副本 |
| 名称相同但 ProjectId 不同 | 作为两个项目展示，禁止自动合并 |
| 对象键存在且 SHA-256 相同 | 幂等复用 |
| 对象键存在但 SHA-256 不同 | 拒绝覆盖并标记冲突 |
| 只有 v0.200 名称目录 | 标记为旧版备份，进入显式认领 / 迁移流程 |

任何“保留本地覆盖云端”操作也必须先创建可恢复的云端历史版本，或明确告知用户提供商未启用版本控制且旧清单将不可恢复。

## 8. 删除语义

### 删除本地项目

- 删除本地项目记录和成员关系。
- 不删除本地资源文件和资产索引。
- 不删除云端项目副本。
- 若云端清单仍存在，云备份管理将其显示为“仅云端”。

### 删除云端项目副本

- 只删除所选备份配置中的项目清单和资源对象。
- 删除前重新读取清单并逐个核验目标对象。
- 不删除本地项目、成员关系和本地文件。
- 多提供商项目只影响用户明确选择的提供商。

### 删除项目资源

- “移出项目”只修改成员关系。
- 下一次同步应生成不再包含该成员的新清单。
- 是否清理不再被任何清单引用的云端对象，必须作为单独的“清理未引用对象”操作，不能静默执行。

## 9. 项目取回

项目整体取回应按以下顺序执行：

1. 下载并校验项目清单。
2. 识别本地是否已有相同 ProjectId。
3. 展示资源数、总大小、缺失对象、冲突和目标工作目录。
4. 将每个资源下载到临时文件并校验大小与 SHA-256。
5. 原子落盘并登记 Asset、AssetLocation 和项目成员关系。
6. 全部资源处理后记录项目取回结果；部分失败保持可重试。

本地存在同名但不同 ProjectId 的项目时不得合并。可以用名称后缀区分显示，但必须保留各自身份。

## 10. v0.200 迁移

迁移旧备份时：

1. 读取本机已有的资产、项目成员、存储位置和上传审计。
2. 仅在关系唯一且校验通过时，将名称目录认领为某个 ProjectId。
3. 为认领后的项目生成清单，但默认不搬移或重命名旧对象。
4. 清单可暂时引用旧对象键，后续再提供显式“升级云端布局”。
5. 同名项目、缺少本地关系或校验不完整时保持“旧版未认领”，由用户选择。
6. 迁移必须幂等、可中断，并记录逐项目结果。

## 11. 实施顺序

1. 增加项目云端清单模型、数据库迁移和单元测试。
2. 为现有同步写入 ProjectId 清单，保留旧对象键读取能力。
3. 将云备份管理从名称前缀分组改为清单 / ProjectId 分组。
4. 增加同名不同 ID、同 ID 分叉和旧版目录识别。
5. 实现项目整体取回和“仅云端”项目导入。
6. 实现项目级远端删除、部分失败重试和审计。
7. 提供旧版备份认领与可选布局升级。

每一步都必须覆盖多提供商、取消、网络失败、重复执行、同名项目和旧数据兼容测试。
