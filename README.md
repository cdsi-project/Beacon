CDSI Beacon 是 CDSI 的本地资产发现与索引应用。它在创作者自己的 Windows 设备上扫描所选目录，建立独立于文件路径的资产与位置记录。扫描和分析不会修改源文件；复制、移动、云端备份、取回或删除备份只会在用户明确选择并确认后执行。

当前版本为 **v0.2.13**，源码以根目录 `VERSION` 为唯一版本来源。仓库已经形成可运行的 Windows 桌面闭环：受管工作目录、多扫描目录及空闲扫描计划、项目化资产管理、显式 Git 项目同步与本地状态管理、阿里云 OSS / 腾讯云 COS / 七牛云 Kodo 多目标备份与校验、云端取回、重复文件检测、基础媒体元数据、OpenWeb 文章发布、本地数据库冗余、Gitee 新版本检查和运行日志。

## 当前能力

- 主窗口启动时默认最大化，并保留标准标题栏、任务栏和窗口还原操作
- Windows 可执行文件内嵌由 Beacon 标志生成的多尺寸应用图标，用于资源管理器、任务栏和窗口标题栏
- 顶部提供“文件、扫描、资产、视图、工具、设置、帮助”一级菜单；“设置”可直接打开设置窗口，其他菜单命令与资产右键和既有确认流程复用同一业务操作
- 主界面移除重复的设置、任务中心、开始扫描和取消按钮，资产视图获得更多垂直空间；对应操作统一从顶部菜单进入
- “扫描”菜单可选择常规扫描或完整校验扫描，并可取消当前任务或刷新资产索引
- “任务中心”实时显示当前任务状态、进度、处理路径和数据目录，并可取消支持取消的任务；“工具 > 运行日志”可查看当前会话及历史日志，并可打开本机日志目录
- 主窗口进度区位于选项卡内容下方、状态栏上方；空闲时自动收起，扫描、传输或发布任务运行时显示阶段、进度条和当前处理路径
- Beacon 将启动、正常退出和界面操作错误写入本机 <code>%LOCALAPPDATA%\CDSI\Logs</code>；窗口创建前发生启动异常时也会在此生成诊断日志，写入前会遮蔽常见密码、令牌、签名和 URL 查询参数
- 首次启动配置一个受管工作目录，并自动创建 <code>Inbox</code>、<code>Assets</code>、<code>Exports</code>、<code>Cache</code>、<code>Temp</code> 和 <code>System</code>
- 工作目录可后续修改；切换时不搬移、不删除旧目录中的任何文件
- SQLite 使用一致性快照自动冗余到 <code>System/DatabaseBackups</code>；启动、数据库发生变化后的每小时检测、设置变更和正常退出均会检查是否需要生成新快照
- 将受管工作目录的 <code>Inbox</code> 作为受管扫描入口
- 添加多个外部扫描目录，并可在目录列表右键停用、启用或软移除
- 添加外部扫描目录时，可通过复选框同时选择视频、音频、图片、文档、其他等扫描策略，默认全部勾选；也可勾选“自定义扩展名”并添加 `.mp4`、`.mov`、`.psd` 等白名单，分类与扩展名按“任一匹配”组合
- 每个外部扫描目录可独立勾选“空闲时扫描”，并按分钟、小时或天设置间隔；只有 Beacon 没有正在执行的任务且没有打开设置或确认窗口时才会启动，到期但忙碌的计划自动顺延
- 设置完成后可选择“开始扫描”或“关闭”；“开始扫描”只扫描本次新增或重新启用的目录，“关闭”只保存设置，顶部“扫描”菜单仍用于主动全量重扫
- 外部扫描目录固定为只读策略；扫描、索引、哈希和元数据提取不会修改源文件
- 资产列表支持单选、Ctrl/Shift 多选；右键会保留或扩展批量选择
- 资产列表右键支持为单个或多个资产批量添加“素材”“文章”或自定义标签；已全选的标签可再次点击移除，半选状态表示部分所选资产已有该标签
- 资产列表右键支持“从资产列表中移除（不删除）”；仅持久隐藏所选资产，本地文件、资产记录、云端备份和项目成员关系保持不变
- 资产列表显示全局行号，每一列均可独立调整宽度；列表由 SQLite 分页加载，每页可选择 100、200 或 500 条，支持上一页、下一页
- 资产列表显示修改时间和索引时间；索引时间取自本机最近一次写入索引记录的 <code>discovered_at</code>
- 资产列表显示完整的 SHA-256 文件校验值；尚未计算的资产显示 <code>-</code>，列宽可自由调整
- 资产列表可按视频、音频、图片、文档或其他类型、已有扩展名、资产标签及创建日期范围组合搜索；扩展名选项随文件类型联动，搜索条件在 SQLite 分页查询前执行
- “资产目录”页签按本地父目录汇总资产数、可用与缺失数量、可用空间；右键可打开目录位置，或经确认后将目录持久排除出后续扫描和资产视图，源文件保持不变
- 资产右键菜单可在 Windows 文件资源管理器中定位并选中当前文件
- 资产右键菜单可打开当前资产的所在项目；只有一个项目时直接定位，属于多个项目时先选择目标项目，并在“项目管理”中选中对应资产
- “项目管理”页签可创建视频、音频、图片、文字或综合类型的项目；新建项目默认不开启云端备份，勾选“开启云端备份”后，可从凭据有效的阿里云 OSS、腾讯云 COS、七牛云 Kodo 配置中勾选 1 个或多个目标
- 绑定多个目标的项目在同步时会依次备份到所有已勾选目标，并分别保存上传审计；项目列表显示目标数量、提供商和创建时间并支持 <code>Ctrl/Shift</code> 多选，双击项目可修改名称和类型，项目 ID、创建时间、成员及备份绑定保持不变；项目资产列表显示短资源 ID、加入时间和备份状态，两张列表的每一列均可独立调整宽度
- 项目列表右键支持“同步到云端”和“同步到Git”；Git 二级菜单按配置名称列出仓库 1、仓库 2 等可用仓库，仅支持单个项目。项目仍可单选或多选删除，删除只清理本地项目及成员关系并记录审计，不删除资产文件、Git 仓库内容或已有云端备份。项目内资产可单选或多选右键“移出项目”，只移除成员关系，不删除文件、资产索引或云端备份
- 从资产列表右键“加入项目”可直接新建项目或选择最近的 3 个项目；项目超过 3 个时通过“更多...”打开完整选择，新建后所选资产自动加入，同一资产可属于多个项目
- 新的云端备份必须以项目为单位：资产列表中的“同步到云端”只提供所选资产共同所属的项目；没有共同项目时，可先加入已有项目或新建项目再同步
- 将项目内全部可用资产同步到每个目标的“项目名称/”目录，文件名保持本地原名，并执行上传进度和完整性校验
- 主界面提供“云备份管理”页签，按对象键中可解析的单层目录前缀组织 Beacon 已登记的阿里云 OSS、七牛云 Kodo 和腾讯云 COS 对象；无法解析前缀的旧对象归入“未归属项目”。该分组不读取本地项目关系，也不代表稳定项目身份。左侧显示分组的云提供商、资源数、副本数、占用空间和最近备份时间，右侧显示所选分组的云端备份；可按本地文件名、云端文件名、对象键、项目、备份配置或提供商搜索，双击备份可打开当前可用的本地文件位置，右键可单选或多选取回、删除所选云端备份，也可在左侧右键删除该分组内全部已登记备份
- 复制到工作目录时使用 <code>Assets/&lt;AssetId&gt;/&lt;原文件名&gt;</code>，保持同一个逻辑资产身份
- 本地复制使用临时文件和流式 SHA-256 校验，不覆盖内容不同的已有文件
- 移动必须再次确认完整源文件列表；只有副本校验并登记成功后才删除源文件
- 复制、移动和每个文件的成功/失败状态持久化到 SQLite 操作审计
- 一次扫描全部已启用目录；离线磁盘或 NAS 标记为不可用后继续处理其他目录
- Windows 下使用 Volume GUID 和卷序列号识别本地卷；移动设备盘符变化时只更新 SQLite 路径映射，不重新扫描或哈希文件
- 运行期间监听设备到达和移除通知；设备拔出后资产位置标记为“设备离线”而不是“位置缺失”，重新插入后进入待确认状态
- 检测嵌套或重叠扫描目录并提示，位置身份仍按设备和规范化路径保持幂等
- 在“备份配置”中添加多个阿里云 OSS、七牛云 Kodo 或腾讯云 COS 配置；双击配置可编辑，右键可编辑、复制 Endpoint 或 Bucket 名称以及删除本机配置
- 在设置页添加多个 OpenWeb 源站；双击源站可编辑，右键可编辑、打开、复制域名、设为默认或删除本机配置；域名规范化后持久化到本机 SQLite
- 在设置页添加多个 GitHub 或 Gitee（码云）仓库配置；双击配置可编辑，右键可编辑、打开平台网站、复制仓库地址、设为默认或删除本机配置，支持密码与 SSH 两种访问方式
- 密码方式使用 HTTPS 仓库地址，用户名和密码分别配置；GitHub 可将个人访问令牌作为密码。SSH 方式使用 SSH 仓库地址，默认查找用户 <code>.ssh</code> 目录中的 Ed25519、ECDSA 或 RSA 密钥对
- 未发现 SSH 密钥时由界面提示；只有用户确认后才打开系统 <code>ssh-keygen</code> 交互程序，Beacon 不会静默生成或覆盖密钥，也不会读取私钥
- 保存 Git 配置不会自动连接、克隆、提交或推送文件；只有用户在“项目管理”中明确选择项目、仓库并确认“同步到Git”后，Beacon 才会创建临时工作副本、提交项目清单及资产并推送到所选分支
- 主界面提供“Git项目管理”页签，按最近同步时间显示项目、类型、Git 配置、平台、仓库地址、分支、最近提交、资产数量、大小和本地状态；可按项目、仓库、平台、分支或提交搜索，双击可定位本地项目，右键可重新同步、打开所在项目、打开仓库或复制仓库地址
- 主界面顶部 Banner 采用内容驱动的高 DPI 自适应布局，系统显示缩放增大时会自动扩展高度，避免标题、说明或版本号被裁切
- 应用启动完成后异步读取 Gitee 仓库的 <code>VERSION</code> 检查新版本；“帮助 → 检查更新”可手动检查，发现新版本后由用户确认是否打开 Gitee 发布页，不自动下载或执行程序
- 每个源站独立配置 WordPress 用户名和应用程序密码；发布 Markdown/TXT 资产时默认选中默认源站，也可临时切换目标源站
- Markdown 发布支持 YAML Front Matter 中的 <code>slug</code>、<code>categories</code>、<code>category</code>、<code>tags</code> 和 <code>tag</code>；分类和标签按名称匹配，不存在时在用户明确发布文章的过程中创建
- 保存资产与 WordPress 文章的映射，重复发布同一资产时更新原文章
- 如果已映射文章在 WordPress 中被删除或失效，发布时会自动新建文章并用新文章 ID 更新本地映射
- 按对象存储兼容规则校验 Bucket，并规范化提供商、Endpoint、地域和 HTTPS 设置
- SQLite 只保存非敏感配置；AccessKey Secret、各源站的 WordPress 应用程序密码和 Git 密码按配置独立保存到 Windows 凭据管理器
- 在资产列表中显示稳定的资产 ID，资产身份不依赖文件名或存储位置
- 当前界面的项目同步路径在上传前再次校验所选资产的项目成员关系，不会通过该路径备份未加入项目的资产；底层保留旧式无项目备份入口用于兼容既有记录
- 新备份的远端对象使用 <code>storage_profile_id + &lt;项目名称&gt;/&lt;原文件名&gt;</code> 标识；旧版本创建的 <code>assets/&lt;AssetId&gt;/...</code> 备份记录仍可校验和取回
- 上传以只读流处理本地文件；大文件使用分片上传，并将 UploadId 和已完成分片保存到 SQLite 以支持重试续传
- 上传前拒绝覆盖同一对象键下内容不同的对象；相同大小和 SHA-256 的对象可幂等复用
- 上传完成后通过 HEAD 校验对象存在性、大小和 <code>cdsi-sha256</code> 元数据，再登记为健康远端位置
- 资产列表的“备份状态”和“备份时间”紧邻“所属项目”显示；默认状态为“未备份”，存在健康副本时按提供商显示“OSS”“七牛”“S3”等并使用绿色字体，同一资产的多个提供商合并显示；选中资产后，下方两行紧凑详情显示文件名、类型、大小、时间、标签、备份信息和路径
- 资产列表的“备份时间”列显示最近一次健康备份完成或校验时间；没有健康备份时显示 <code>-</code>
- 上传进度显示本次实际网络传输速度，任务、文件结果和失败原因写入本地审计
- 资产列表右键支持单选或多选“从 OSS 取回”；每个资产可在确认窗口选择一个带有效凭据且已通过校验的 OSS 副本
- 取回默认恢复到 <code>Assets/&lt;AssetId&gt;/&lt;原文件名&gt;</code>，也可显式选择其他本地目录；用户指定目录登记为外部位置，不改变逻辑资产 ID
- OSS 下载使用流式传输和同目录临时文件，完成后校验大小与 SHA-256 再原子落盘；已有相同内容会直接复用，已有不同内容则拒绝覆盖
- 取回界面显示进度和下载速度，任务及逐文件结果写入本机 SQLite；失败后可从资产右键菜单重新发起
- 编辑配置时不读取或回显已有 Secret，留空会保留原凭据
- 删除备份配置只删除本机记录和凭据，不删除 Bucket 或云端对象
- 配置 OSS 不会触发连接、上传或同步
- 默认忽略 <code>.git</code>、<code>.vs</code>、<code>node_modules</code>、<code>vendor</code>、<code>bin</code>、<code>obj</code> 等目录
- 默认不跟随符号链接和 junction
- 识别常见文件扩展名与 MIME 类型，未知格式仍可索引
- 以异步流式读取计算 SHA-256，不把大文件载入内存
- 扫描与哈希分为两个阶段，资产索引完成后立即显示
- 默认仅对同尺寸的重复候选计算 SHA-256，避免无条件读取每个大视频
- 勾选“完整校验”时补齐所有未哈希文件，重复文件仍以完整 SHA-256 为准
- 基于文件大小和修改时间复用缓存，避免重复哈希
- 按 SHA-256 生成重复文件组并在独立标签页展示，双击或右键可打开文件位置
- 通过可扩展的提取器注册表处理资产元数据
- 在本机只读提取常见图片、音频和视频的基础属性
- 提取图片/视频尺寸、媒体时长、编码、比特率、采样率和声道数
- 提取标题、艺术家和专辑等常用媒体标签
- 以文件大小、修改时间和管线版本缓存元数据结果
- 扫描过程不提取或缓存文件正文；用户明确发布 Markdown/TXT 到 OpenWeb 时才只读读取所选源文件
- 在资产列表中展示分辨率、时长和编码摘要
- “统计”页签通过饼图展示视频、音频、图片、文本/文档及其他类型的资产构成，并汇总可用本地文件、不可用资产、已备份与未备份资产、备份覆盖率、占用空间和视频总时长
- 将资产、位置、扫描根和扫描任务持久化到 SQLite
- 同一设备和路径重复扫描时保持幂等
- 文件消失时仅将本地位置标记为 <code>Missing</code>，保留逻辑资产
- 只有完整且无遍历错误的扫描才更新缺失状态，避免权限或临时 IO 故障造成误报
- 在 WinForms 中显示扫描进度、错误计数和资产列表
- 应用采用单实例运行；重复启动只会恢复并激活已有窗口，不会重复初始化数据库或启动扫描任务
- 首次启动为当前 Windows 用户下的 Beacon 安装实例生成 UUID 格式的全局唯一客户端 ID，独立保存于本机数据目录，不随 SQLite 数据库、工作目录或数据库快照迁移；“关于”面板可查看和复制该 ID
- 在 Windows 标题栏和应用页眉显示当前构建版本
- 哈希阶段显示文件数、读取字节数与吞吐率
- 支持取消扫描或哈希；已完成哈希会保留，下次从未完成文件继续
- 支持取消元数据提取；已完成结果会保留，下次从未完成文件继续
- 单文件错误不会中断整个任务

## 项目与云备份边界

Beacon 当前以“项目”作为新云端备份的发起边界：资产可以先被索引而暂时不属于项目，但只有加入项目后才能同步到云端。取回和删除仍针对用户明确选择的已登记副本；项目删除、项目成员移除、云端备份删除和本地文件删除是相互独立的操作，任何一项都不会隐式触发其他项。

当前 v0.2.13 的本地项目已经拥有稳定项目 ID，并支持修改名称和类型，但云端对象仍使用 <code>&lt;项目名称&gt;/&lt;原文件名&gt;</code> 作为对象键，并由“云备份管理”按对象键前缀分组。这是兼容阶段的实现，不应把项目名称视为永久身份：本地改名不会迁移既有云端对象，同一备份配置下的同名项目仍可能发生对象键冲突，也不能仅凭目录名可靠区分来自不同设备的逻辑项目。

下一阶段将为云端项目引入稳定 <code>ProjectId</code> 和项目清单（manifest），使项目名称可修改但身份不变，并支持项目级状态、冲突确认、整体取回和跨设备重建。详细约束与迁移方案见 [项目与云备份模型](docs/CDSI_BEACON_PROJECT_CLOUD_MODEL.md)。

## 基本使用

1. 首次启动时选择 CDSI 工作目录。应用只会自动创建工作目录结构，不会搬移或整理已有文件。
2. 在“设置”中添加需要索引的本地目录，并勾选一个或多个扫描策略，默认勾选全部文件分类。如需扫描分类之外的格式，可同时勾选“自定义扩展名”并添加白名单；文件匹配任一已勾选分类或扩展名时就会被扫描。可按目录启用“空闲时扫描”并设置分钟、小时或天间隔；现有目录升级后默认关闭。点击“开始扫描”只处理本次设置的目录；点击“关闭”只保存，不扫描。外部扫描目录保持只读。
3. 如需刷新已有目录，再点击主界面的“扫描”执行全部已启用目录的重新扫描。扫描只索引各目录配置的文件类型，哈希和媒体元数据处理继续分阶段完成。
4. 使用“全部资产”页顶部的搜索条件定位文件，或切换到“资产目录”“重复文件”“项目管理”“云备份管理”等页签查看不同视图。
5. 复制、移动、项目同步到 OSS、OSS 取回和 OpenWeb 发布都必须由用户从界面明确发起；新的 OSS 备份要求资产先加入项目。取回时可选择本地目标和远端来源，发布文章时可确认或切换目标源站。单纯扫描或搜索不会修改、上传或下载文件。

## 备份配置与使用

Beacon 当前支持使用阿里云 OSS、七牛云 Kodo 或腾讯云 COS 保存可校验的资产副本。Beacon 不会代替用户开通云服务、创建 Bucket、创建访问凭据或修改云端权限，也不会因为保存配置而自动连接或上传文件。

### 云服务商官方文档

- [阿里云对象存储 OSS 官方文档](https://help.aliyun.com/zh/oss/)
- [七牛云对象存储 Kodo 官方文档](https://developer.qiniu.com/kodo)
- [腾讯云对象存储 COS 官方文档](https://cloud.tencent.com/document/product/436)

### 在 Beacon 中添加配置

打开“设置”一级菜单，进入“备份配置”页签，点击“添加配置”并填写：

| 配置项 | 填写说明 | 示例 |
| --- | --- | --- |
| 提供商 | 选择“阿里云 OSS”“七牛云 Kodo”或“腾讯云 COS” | 腾讯云 COS |
| 配置名称 | 仅用于本机区分多个备份配置 | 七牛主备份 |
| Endpoint | Bucket 所在地域的访问节点，不包含 Bucket 名称、路径或查询参数 | <code>s3.cn-east-1.qiniucs.com</code> |
| Bucket | 阿里云 Bucket、七牛 S3 空间名称，或腾讯 COS 的 <code>BucketName-APPID</code> | <code>examplebucket-1250000000</code> |
| 地域 / Region ID | 与 Bucket 和 Endpoint 对应；七牛云 Kodo、腾讯云 COS 必填 | <code>ap-guangzhou</code> |
| AccessKey ID / SecretId | 阿里云 AccessKey ID、七牛 AccessKey 或腾讯 SecretId | 由云服务商生成 |
| AccessKey Secret / SecretKey | 阿里云 AccessKey Secret、七牛 SecretKey 或腾讯 SecretKey；首次保存必填 | 由云服务商生成 |
| 使用 HTTPS | 建议始终勾选 | 已勾选 |

Endpoint 可填写主机名，也可填写与“使用 HTTPS”选项一致的完整 URL，但不能填写 <code>Bucket.Endpoint</code> 形式的 Bucket 域名。切换提供商时必须重新填写 Secret，防止沿用另一家服务商的旧凭据。保存后，非敏感字段写入本机 SQLite，Secret 独立写入当前 Windows 用户的凭据管理器。当前版本保存配置时不执行连接测试；首次备份或取回成功，才表示提供商、Endpoint、Bucket、区域、凭据和权限可以协同工作。

配置列表支持混合保存多个提供商和 Bucket。双击配置可编辑；右键可编辑、复制 Endpoint、复制 Bucket 名称或删除本机配置。删除配置不会删除 Bucket、云端 Object 或已经登记的资产记录。

### 备份、同步与取回

1. 先在“项目管理”中创建项目，并通过“全部资产”右键菜单把资产加入项目。一个资产可以属于多个项目。
2. 在“全部资产”中单选或多选本地可用资产，右键选择“同步到云端”。菜单会列出所有所选资产共同所属的项目；没有共同项目时，选择“加入项目并备份...”可加入已有项目或新建项目后继续。
3. 在确认窗口选择目标备份配置并核对项目和源文件清单；确认后才开始上传。即使随后取消上传或上传失败，已完成的项目分类仍会保留。
4. 也可在“项目管理”中右键项目并选择“同步到云端”。项目名称作为每个对象存储目标的目录名，项目内文件名保持原样，即 <code>&lt;项目名称&gt;/&lt;原文件名&gt;</code>。同一项目存在同名文件时会拒绝同步，避免多个资产写入同一个对象。
5. 大文件自动使用分片上传，失败或取消后可重试续传。上传完成后，Beacon 会通过对象大小和 <code>cdsi-sha256</code> 元数据校验结果；通过校验的备份在资产列表中以绿色显示。
6. 需要恢复时，可在“全部资产”中选择资产并右键“从 OSS 取回”，也可在“云备份管理”中先选择项目，再选择一个或多个副本后右键“取回”。只能选择本机已登记、凭据有效且完整性状态正常的云端副本；目标可选 CDSI 工作目录或用户指定目录。
7. 下载先写入临时文件，大小和 SHA-256 校验通过后才登记为本地位置。目标存在相同内容时直接复用，存在不同内容时拒绝覆盖。旧版本以 <code>assets/&lt;AssetId&gt;/...</code> 保存的备份同样可以取回。
8. 在“云备份管理”中右键选择“删除备份”会永久删除所选云端对象及其本机备份映射。远端对象仍存在时，Beacon 会在删除前核对对象大小和 SHA-256 并再次确认；远端对象已经不存在时只清理本机失效映射。两种情况都不会删除本地文件或项目关系。
9. 在左侧“备份项目”中右键选择“删除备份项目”，可一次删除该项目下的全部云端副本。此操作同样逐个核验并要求确认，不会删除本地项目、项目成员关系或本地文件。

Beacon 保存的是 Bucket、对象键、大小、SHA-256 和校验状态，不依赖公开 URL。Bucket 可以保持私有，无需为备份文件开放匿名访问。

### 项目同步到 Git

在“设置 > Git配置”中保存一个或多个 GitHub、Gitee 仓库后，在“项目管理”的项目列表中右键单个项目，选择“同步到Git”，再从二级菜单选择目标仓库。确认窗口会显示仓库、分支、资产数量与总大小；确认后 Beacon 使用系统安装的 Git，在 <code>&lt;工作目录&gt;\Temp\GitSync</code> 创建隔离的临时工作副本，将项目资产按原文件名复制到仓库根目录，写入 <code>.cdsi-project.json</code> 项目绑定清单，创建提交并推送。源资产始终只读，临时工作副本在操作结束后清理。

一个仓库通过清单绑定一个稳定项目 ID；如果仓库已经绑定其他项目，Beacon 会拒绝合并。远端已有但不属于当前 Beacon 项目的同名不同内容文件不会被覆盖，远端多余文件也不会被自动删除。相同内容重复同步不会创建新提交。HTTPS 使用 Windows 凭据管理器中保存的密码或访问令牌，SSH 使用用户选择的密钥对；两种方式都不会把 Secret 写入仓库或 SQLite。Beacon 不会自动配置 Git LFS，单个文件不小于 50 MB 时会在确认前提示，实际文件大小限制仍由 Git 托管平台决定。

同步成功后，Beacon 在本机 SQLite 中按“项目 ID + Git 配置 ID”保存最新同步状态。“Git项目管理”只读取这些本地记录，打开或搜索页签不会连接远端。删除本地项目或 Git 配置不会删除远端仓库，也不会清除这条历史记录；此时面板会显示“项目已删除”或“Git配置已删除”。重新同步仍使用与项目列表相同的确认窗口，只有本地项目和 Git 配置都可用时才能执行。

### 常见问题

| 提示或现象 | 检查方法 |
| --- | --- |
| <code>403 AccessDenied</code> | 检查 AccessKey 是否拥有目标 Bucket 的读写及分片上传权限，并确认 Bucket 名称正确。 |
| <code>404 NoSuchKey</code> | 检查已登记的对象是否被其他工具删除或改名，以及当前配置是否指向原 Bucket。Beacon 不会自动删除云端对象。 |
| <code>SignatureDoesNotMatch</code> 或凭据无效 | 重新核对提供商、AccessKey ID/Secret 和 Region ID；遗失 Secret 后应在云服务商控制台创建并轮换新的访问凭据。 |
| Endpoint 错误、超时或无法连接 | 确认 Endpoint 与 Bucket 地域一致；阿里云普通电脑使用外网 Endpoint，七牛云使用对应区域的 S3 Endpoint，腾讯云使用 <code>cos.&lt;Region&gt;.myqcloud.com</code>。 |
| 提示缺少 AccessKey Secret | 双击配置重新编辑并填写 Secret；凭据按 Windows 用户保存，切换账户或迁移数据库不会自动迁移凭据。 |
| 目标对象已存在且内容不同 | Beacon 默认拒绝覆盖。检查项目内的同名文件或云端已有对象，处理冲突后重试。 |

对象存储容量、请求次数、下行流量、低频或归档数据取回等费用由所选云服务商按 Bucket 配置计费。Beacon 不会设置生命周期、版本控制、服务端加密或归档解冻策略；启用这些云端功能前，应确认不会导致备份被自动删除、无法直接取回或产生额外费用。

### Markdown 发布元数据

Markdown 文件可在正文前使用 YAML Front Matter 设置 WordPress slug、分类和标签：

~~~yaml
---
slug: creator-tools
categories:
  - 创作工具
  - 教程
tags: [CDSI, 本地优先]
---

# 正文标题
~~~

Front Matter 不会进入文章正文。<code>categories</code> 和 <code>tags</code> 可使用 YAML 列表或逗号分隔文本，单数形式 <code>category</code>、<code>tag</code> 也受支持。未声明的字段不会清空 WordPress 文章中原有的 slug、分类或标签；显式空列表会请求清空对应分类或标签。WordPress 用户需要具备查询及分配分类和标签的权限；当指定名称不存在时，还需要创建分类或标签的权限。

## 数据安全

CDSI Beacon 采用本地优先、默认非破坏性的处理方式，但不能替代操作系统权限管理和独立备份。以下说明适用于当前版本。

### 文件安全

- 扫描、搜索、哈希和媒体元数据提取只读取用户明确配置的目录，不会自动重命名、移动、删除、去重或上传源文件。
- 从项目中移出成员、停用扫描目录或发现文件离线/缺失时，只更新本机索引状态，不删除物理文件。
- 复制到工作目录时先写入临时文件并校验 SHA-256；目标位置存在内容不同的同名文件时拒绝覆盖。
- “移动”是需要用户确认的显式操作。系统只在目标副本写入、校验和登记成功后删除源文件，但移动仍会改变文件位置，执行前应核对确认清单并保留必要备份。
- OSS 备份只上传用户明确选择并确认的文件。上传使用只读流，拒绝覆盖同一对象键下内容不同的远端对象，完成后验证对象大小和 SHA-256 元数据。
- 云端取回只下载用户明确选择并确认的健康备份。下载先写临时文件，大小和 SHA-256 校验通过后才登记；目标已有不同内容时拒绝覆盖，失败的临时文件不会成为资产位置。
- 删除云端备份只处理用户明确选择并确认的对象；远端对象仍存在时会在删除前核对大小和 SHA-256，已经不存在时只清理本机失效映射。操作不会删除本地文件或项目关系。
- 删除备份配置不会删除 Bucket 中的对象；文件离线或扫描暂时失败也不会删除逻辑资产记录。

### 密码与凭据

- OSS AccessKey Secret、WordPress 应用程序密码和 Git 密码保存在当前 Windows 用户的凭据管理器中，不写入 <code>cdsi.db</code>；凭据按配置隔离保存，编辑配置时不会读取并回显已有密码。
- SQLite 会保存连接所需的非密码信息，例如 AccessKey ID、Endpoint、Bucket、各 WordPress 源站域名和用户名，以及 Git 平台、仓库地址、访问方式、用户名、默认分支、SSH 公钥路径和最近同步提交。AccessKey ID、仓库地址和提交哈希不是 Secret，但仍不建议公开。
- 当前应用没有独立的主密码，也没有对 SQLite 数据库进行应用层加密；本机数据的访问控制依赖 Windows 账户权限。建议为 Windows 账户设置强密码。
- SSH 私钥始终由系统 OpenSSH 和用户管理，Beacon 只检查对应私钥是否存在并保存公钥路径，不读取、复制或上传私钥。“生成新密钥”会在 <code>.ssh</code> 中选择未占用的 Beacon 专用文件名，不覆盖已有密钥；生成时应设置口令，并将公钥添加到所选 GitHub 或 Gitee 账号。
- WordPress 发布固定使用 HTTPS。备份配置允许选择 HTTP 或 HTTPS；为避免凭据和文件在传输中暴露，应始终启用 HTTPS。
- 建议为 OSS 使用权限最小化、可轮换的专用凭据。备份至少需要目标对象的写入和读取元数据权限，取回需要 <code>oss:GetObject</code>，删除云端备份需要 <code>oss:DeleteObject</code>。缺少删除权限不影响普通备份和取回，但删除会失败并保留本地映射。为 WordPress 使用应用程序密码而不是账户主密码；凭据泄露后应立即在服务端撤销并重新生成。

### 隐私与网络

- 本机 SQLite 位于 <code>%LOCALAPPDATA%\CDSI\cdsi.db</code>。其中包含文件名、绝对路径、大小、时间、SHA-256、媒体元数据、项目及成员关系、远端对象键、Git 项目同步记录、操作审计和发布映射等隐私信息；能够访问该数据库的用户可能据此了解本机资产结构。
- Beacon 使用 SQLite Online Backup API 将数据库一致性快照保存到 <code>&lt;工作目录&gt;\System\DatabaseBackups</code>，每个快照带有包含 SHA-256、SQLite 版本、Beacon 版本和源数据库时间的 JSON 清单。数据库没有变化时不会重复生成自动快照；“文件 → 立即备份数据库”可强制创建一份快照。
- 本地数据库快照采用分层保留策略：保留最近 24 份、最近 14 个日期各一份及最近 12 个月各一份。快照创建后会执行 SQLite 快速完整性和外键检查，失败的临时文件不会成为正式备份。
- 本地快照仍位于用户选择的工作目录中，当前未进行应用层加密，也不能防御工作目录所在磁盘整体损坏。重要项目仍应把工作目录或数据库快照另存到其他物理磁盘；内置快照恢复界面将在后续版本补充。
- 当前扫描流程不提取或保存文件正文。
- 当前版本不会因为扫描、搜索、创建项目或保存配置而传输文件。应用启动完成后以及用户选择“检查更新”时，会向 Gitee 发起只读 HTTPS 请求并只读取公开仓库的 <code>VERSION</code>；该请求不上传资产、路径、配置、凭据或客户端 ID。保存 Git 配置不会连接、克隆、提交或推送仓库；文件传输或远端变更只在用户明确执行 Git 项目同步、云端备份、取回、删除或 OpenWeb 发布并完成相应确认后发生。Git 同步会把所选项目内文件传输到所选仓库；发布过程中可能按 Markdown Front Matter 创建所声明但尚不存在的 WordPress 分类或标签。
- 云端备份将所选原始文件直接发送到用户确认的对象存储；项目绑定多个目标时，同一文件会依次发送到每个目标。OSS 取回将所选远端对象直接下载到用户确认的本地目录；OpenWeb 发布会读取所选 Markdown/TXT，并将文章标题和转换后的 HTML 发送到用户配置的 WordPress。对应服务商的访问控制、保留策略和合规责任由用户配置和管理。
- 当前版本尚未接入 CDSI Server，也没有后台遥测上传。运行日志、操作审计和错误信息仅保存在本机；日志仍可能包含文件路径、对象键和账号标识，向他人提供数据库、日志内容或错误截图前应先检查。

## 资产搜索

资产列表支持以下条件组合搜索：

- “文件类型”：全部类型、视频、音频、图片、文档或其他
- “扩展名”：从本机已经索引的扩展名中选择，例如 <code>.mp4</code>、<code>.jpg</code>、<code>.md</code>；切换文件类型后只显示该类型下的扩展名
- “标签”：从本机标签库中选择，包括预设标签和已创建的自定义标签
- “创建时间”：开始日期和结束日期可分别启用，结束日期包含所选当天

切换文件类型时，兼容的扩展名选择会保留，不兼容的选择会自动回到“全部扩展名”。选择条件后点击“搜索”。多个条件之间按 AND 组合，例如“视频 + <code>.mp4</code> + 素材”只显示带“素材”标签的 MP4 视频。搜索由 SQLite 在分页前执行，因此结果覆盖全部索引资产，而不只是当前页。点击“重置”可清空全部条件、恢复全部扩展名并回到完整资产列表。

搜索结果仍可选择每页显示 100、200 或 500 条，并使用“上一页”“下一页”浏览；表格列宽调整不影响搜索条件和分页状态。

## 资产统计

“统计”页签展示整个本地资产索引的汇总，不受“全部资产”列表当前搜索条件或分页影响。资产类型分布饼图按视频、音频、图片、文本/文档和其他五类显示数量与占比；已从资产列表隐藏的资产不计入统计。

资产总数、文件类型和 OSS 备份状态按稳定资产 ID 去重；只要存在一个状态为 <code>Healthy</code> 的对象存储位置，该资产就计为已备份。可用本地文件数和占用存储空间按实际可用的本地文件位置计算，因此同一资产存在多个本地副本时会分别计入磁盘占用。不可用资产表示仍有本地位置记录、但没有可用本地文件的资产。

文件类型根据本地 MIME 和扩展名确定，不依赖媒体元数据提取结果。视频总时长只累加与当前文件大小、修改时间及元数据管线版本一致的有效媒体元数据；文件变化后不会继续使用旧时长。

## 架构

~~~text
CDSI.Agent.WinForms
        |
        v
CDSI.Agent.Application
        |
        v
CDSI.Agent.Core
        ^
        |
CDSI.Agent.Infrastructure
~~~

- <code>CDSI.Agent.Core</code>：领域模型与抽象，不依赖 WinForms、SQLite 或云 SDK。
- <code>CDSI.Agent.Application</code>：扫描、元数据、哈希、受管文件操作和对象存储备份工作流编排。
- <code>CDSI.Agent.Infrastructure</code>：文件系统扫描、媒体元数据提取、SQLite 及一致性快照、Windows 凭据管理器，以及阿里云 OSS、腾讯云 COS、七牛云 Kodo 适配器。
- <code>CDSI.Agent.WinForms</code>：桌面界面与依赖组合根。
- <code>tests</code>：Core、Infrastructure、Integration 和 WinForms 四组自动化测试；文件系统测试只使用隔离的临时目录。

## 版本管理

仓库根目录的 <code>VERSION</code> 是唯一版本来源。构建时，所有程序集和桌面界面都会读取该文件。

版本号使用 <code>x.y.zz</code> 格式，最后一段固定为两位并在 <code>10</code> 至 <code>99</code> 之间递增。例如 <code>1.2.10</code> 的下一版本是 <code>1.2.11</code>，<code>1.2.99</code> 的下一版本是 <code>1.3.10</code>。运行 <code>powershell -NoProfile -File scripts/Increment-Version.ps1</code> 可按该规则自动更新根目录 <code>VERSION</code>。

<code>v0.2.10</code> 是新规则的首个版本，也是旧规则最后一个版本 <code>v0.206</code> 的直接后继。内置版本检查器已经显式处理这条历史分界，不会使用普通三段版本比较把 <code>0.2.10</code> 判定为旧于 <code>0.206</code>。

应用启动后会异步读取 <code>https://gitee.com/cdsi/beacon/raw/master/VERSION</code>，也可通过“帮助 → 检查更新”手动读取。只有通过测试并且对应二进制已准备发布的版本，才应更新默认分支的 <code>VERSION</code>，避免用户收到尚无可用安装包的更新提示。

每次代码版本提交都递增一次，并创建与 <code>VERSION</code> 完全相同的 Git 标签，例如 <code>VERSION=0.2.11</code> 对应 <code>v0.2.11</code>。纯文档修订不单独递增应用版本，也不生成新的二进制发布物。

## 本地数据

应用状态写入：

~~~text
%LOCALAPPDATA%\CDSI\cdsi.db
~~~

客户端安装身份写入：

~~~text
%LOCALAPPDATA%\CDSI\client-identity.json
~~~

客户端 ID 使用随机 UUID 创建，不读取硬件序列号，也不是密码、令牌或授权凭据。身份文件与 SQLite 分离，因此从数据库备份恢复到另一台客户端时不会覆盖新客户端身份。未来接入 CDSI Server 激活时，服务端仍必须对客户端 ID 建立唯一约束，并在检测到克隆身份或极小概率碰撞时重新签发。

数据库一致性快照写入：

~~~text
<CDSI 工作目录>\System\DatabaseBackups
~~~

工作目录由用户首次启动时选择，推荐路径为 <code>D:\cdsi_workspace</code>；如果 D 盘不可用，则使用用户目录下的 <code>cdsi_workspace</code>。切换工作目录不会搬移或删除旧内容。

扫描、索引、哈希和元数据提取只读取扫描目标。手动扫描与空闲扫描使用同一套本地只读流程；启用空闲扫描不会自动上传、下载、移动或删除文件。资产标签、项目及其成员关系保存在本机 SQLite 中，不写入文件内容、不重命名文件，也不改变文件的物理位置。用户可在资产列表中显式复制或移动选中的文件到 CDSI 工作目录；新的对象存储备份要求资产先加入项目，并在确认目标 Bucket、项目和源文件清单后同步，已有的健康远端副本仍可取回。这些操作失败时不覆盖既有本地文件。文件操作审计、上传断点、取回审计和非敏感备份配置保存在本机 SQLite 中；AccessKey Secret 保存在当前 Windows 用户的凭据管理器中。仅配置备份存储、创建标签、创建项目或执行扫描不会自动上传或下载。测试只使用 <code>%TEMP%\cdsi-agent-tests\&lt;随机目录&gt;</code>，不会扫描或清理真实用户目录，也不会连接真实对象存储。

本地卷以 Volume GUID 为主要身份，扫描根和资产位置同时保存卷内相对路径。盘符变化只触发卷枚举和数据库路径重映射，不遍历文件。移动设备离线期间可能在其他电脑上发生内容变化，因此重新接入后的文件位置会先标记为待确认；当前仍需后续扫描完成内容对账，未来可在 NTFS 卷上通过 USN Change Journal 执行增量对账。

schema v27 会永久删除旧版本的 <code>asset_text</code> 表及其中的历史正文记录；全新数据库不再创建该表，也不提供兼容读取或恢复路径。此迁移只清理数据库中的历史提取结果，不会修改或删除原始文件。

schema v28 为每个扫描目录保存是否启用空闲扫描、执行间隔和分钟/小时/天单位。升级已有数据库时默认关闭，不会因迁移立即启动扫描。
